# 1. Overview of the Test Plan

**1.1 Purpose**

The purpose of this test plan is to ensure that the software project functions correctly, meets the specified requirements, and is free of major defects before deployment. The test plan will also assess the software's security and performance.

<br>

**1.2 Scope**

This test plan covers the following features:

- User authentication (login and registration)
- Form validation and error handling
- Performance and security checks 
- Event manipulation (creating/deleting events, steps and instructions)
- Event hosting (live dashboard)

*Note: some test cases have been collapsed into one test case because the tests are run automatically using a script*

<br>

**1.3 Project Description**

The project provides a digital run sheet for a small backstage crew at school. It is designed to make it easier to read instructions by limiting the amount of irrelevant information and by displaying instructions in an intuitive UI. This reduces confusion mid-show and increases operational efficiency. Moreover, the software allows run sheets to be synchronised, ensuring all crew members have an up to date copy of instructions.

The key functions are:
- Authentication system
- Admins can create and edit run sheets
- Admins can 'play' the run sheet during the event and progress it forward
- Crew members can view the run sheet, synchronised with the admin's progression

This project uses HTML, CSS and JavaScript for the front end. Some external libraries have been used, such as DOMPurify. For the backend, Python 3.14.3 is used, alongside the Flask library. It interacts with a SQLite3 database.

<br>

**1.4 Testing Objectives**

- Verify that all features set out in the functional requirements work as intended
- Identify and fix bugs before handing the software to the client
- Ensure project meets:
    - Performance standards
    - Security standards

# 2. Testing Strategy


**2.1 Types of Testing**

Sometimes, multiple testing types will be combined into one test case in order to save time.

*Unit Testing:* 
Testing individual components or functions within the website.

*Integration Testing:* 
Ensuring different modules work together, including communication between frontend and backend.

*System Testing:* 
Verifying the entire system's behavior by ensuring the database actually updates.

*Functional Testing:*
Focuses on the outputs generated by a specific input soley from the user's perspective.

*Performance Testing:* 
Checking page load speed and system response time, especially when the a high volume of data is being loaded.

*Security Testing:* 
Ensuring protection against vulnerabilities like SQL Injection or Cross-Site Scripting (XSS).

<br>

**2.2 Testing Environment**

*Browsers:* 
Firefox, Edge, Chrome, Safari

*Devices:* 
Desktop, Laptop

*Tools:* 
Pytest/JavaScript/GitHub pipelines (for unit and integration tests), Browser DevTools (for performance testing and debugging), OWASP ZAP (for security testing). Microsoft Playwright to emulate Safari on a Windows laptop.

For automated testing, there are two technologies used:
- Frontend: custom functions have been written to perform tests, based on this [article](https://alexwlchan.net/2023/testing-javascript-without-a-framework/). Implementation details can be found in the journal [here](../../journal.md#11052026).
- Backend: Pytest has been implemented with the help of its documentation and StackOverflow discussions.
- GitLab: pipelines have been used to automatically run these test scripts upon every commit to the main and dev branch.
