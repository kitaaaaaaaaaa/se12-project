# Performance

**Page load times are optimized (e.g., lazy loading, minified assets).**

Has this criteria been met? *Partially*

Analysis: Load times have been optimised by reducing the amount of web to third party integrations where possible. HTTP requests have also been reduced in some areas. For example, the app continually pings the server with longer intervals if certain conditions have been met. Further optimisation could occur if assets and code files were minimised, however this was not performed in order to maintain code comments.

<br>

**Database queries are optimised (e.g., indexed where needed).**

Has this criteria been met? *Yes*

Analysis: The back end server has been set to use asncyronous processes using the command `PRAGMA synchronous = NORMAL;`. There is no viable way to assess the impact of database optimisation, but these optimisation measures have been taken.

<br>

**Unnecessary code or API calls have been removed.**

Has this criteria been met? *Yes*

Analysis: After production, it was ensured that any temporary code leftover from development was removed. Any code used for debugging was also immediately removed after debugging was finished, so there should not be any unnecessary code.

<br>

**Caching is used where applicable (e.g., images, API responses).**

Has this criteria been met? *No*

Analysis: Caching was not implemented to any degree due to project time constraints. While the server cache was used to store certain variable data, there was no attempt to cache API responses.
