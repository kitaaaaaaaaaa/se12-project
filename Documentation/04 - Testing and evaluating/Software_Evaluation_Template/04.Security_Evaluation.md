# Security

**User authentication & authorisation are implemented securely.**

Has this criteria been met? *Partially*

Analysis: Passwords are hashed before storing it in the database. The library used to hash passwords is also up to date, since it is managed by the pip installer. The app should ideally be using HTTPS to ensure that MITM attacks cannot occur - this is a major security vulnerability.

<br>

**All input fields are validated and sanitized to prevent SQL Injection/XSS/CSRF.**

Has this criteria been met? *Partially*

Analysis: As outlined in the documented [security measures](../../03%20-%20Producing%20and%20implementing/2.%20Security%20within%20code.md), fields have been validated and sanitised. It could be strengthened even further by validating and sanitising inputs within the backend as well to provide a second line of defense.

<br>

**Passwords are hashed and not stored in plain text.**

Has this criteria been met? *Yes*

Analysis: When directly accessing the database as a developer and viewing the passwords, it can be observed that they are stored in cipher text. Additionally, passwords are hashed in the code before being stored.
