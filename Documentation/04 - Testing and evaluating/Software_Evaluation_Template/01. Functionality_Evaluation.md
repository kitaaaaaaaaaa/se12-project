# Functionality

**The software meets the initial requirements and objectives**

Has this criteria been met? *Yes*

Analysis: All sprints were successfully completed during the Producing and Implementing phase. Functional tests also verified that each main feature works. Since the features align with the intial requirements, the software has met the initial requirements and objectives.


<br>

**Features work correctly without crashes or unexpected behaviour**

Has this criteria been met? *Partially*

Analysis: After each sprint, the feature's functionality has been tested, which includes edge cases. In the testing phase, simulated data was used to model a multitude of different scenarios across different browsers. Any errors were fixed. Thus, features should work correctly without crashes, but there could be some edge cases that were not considered. The project would benefit from collaborating with other developers.


<br>

**Forms and inputs validations and incorrect inputs are handled properly**

Has this criteria been met? *Partially*

Analysis: Extensive input validation has been implemented as outlined in [this page](../../03%20-%20Producing%20and%20implementing/2.%20Security%20within%20code.md). However, the initial criteria says that data validation should occur twice: on the frontend and backend. Due to time constraints, it has been implemented consistently on the frontend, but only on some routes within the backend.

**APIs and third-party integrations (if used) function correctly**

Has this criteria been met? *Yes*

Analysis: In this project, the `app.py` file serves as an API, which is an interface between the frontend client and the database. Throughout development, each feature was tested, which verifies the functionality of the API at the same time. Also, during the testing and evaluating phase, automated tests were run to check if the API functions correctly. All tests were successful, so the API works correctly.
