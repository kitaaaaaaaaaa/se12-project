# Feedback
This page outlines the feedback that was received concerning my project, which primarily comes from my client. It also details how I responded to such feedback.

## Methods of obtaining feedback
Since one of my clients is a senior crew member, I am able to keep in close contact with them. As the project evolved, I had less and less access to teacher who originally agreed to be my client - they were preoccupied with coaching their other HSC students. Therefore, I relied on my younger client and conversed regularly with them.

I conducted informal interviews that allowed us to discuss the effectiveness of the software solution in a real world scenario. I also observed them interact with the application and immediately fixed any issues that arose.

## Summary Of Feedback
### High-Impact Feedback
This requires immediate action before deployment.
| Feedback | Response |
| - | - |
| *"I think the job title should be moved to the left side of the step instruction since it makes it easier to read"* | Since the client already gave me the fix, I will implement the fix and change the UI design. Will only take 30-40 minutes. Failure to implement this would detract from the UX. |
| While testing basic website functionality with my client, they said: *"The website doesn't load...it says not connected."* | This is quite valuable - it means that the connection indicator works well. There is a CORS error which needs to be fixed. I need to add config files so the client can quickly change the backend/frontend IP address. Should be a quick relocation of variables and take 20-30 minutes. |

## Low-Impact Feedback
These suggestions can be addressed after deployment since they are not urgent.
| Feedback | Response |
| - | - |
| *"We should be able to press a button and share what microphones are being used with all team members during an event. It would reduce confusion and make our organisation better."* | I explained that this feature would be extremely complicated to implement and that it falls out of the project scope. It might take 5-6 hours of work to create the new UI and add backend routes. These changes would undoubtedly benefit the current scenario and help crew members organise equipment. |
