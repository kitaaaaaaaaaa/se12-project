# Functional requirements
This lists the requirements that the software must fulfill in order to address the problem.

## Essential features
These features must be implemented in order to address the problem and achieve the desired outcomes.
- A homepage to view all events
- Ability to edit event run sheets before the event
- Function to 'play' the run sheet during the event and for admins progress it forward
- Function for members to view the live run sheet, synchronised with the event admin, filtered by their specific role
    - Their interface must be uncluttered and user-friendly
- Authentication system to distinguish an administrator and a crew member

## Optional features
These features are beneficial, but not required to address the core problem. They are ranked based on how beneficial they are to the scenario.
1. Ability for admin to edit instructions *during* the event
2. Display the estimated time before a step should commence
3. Function to print a paper copy of a run sheet
4. Support for mobile devices
5. Toggle between light and dark mode interface

## Other requirements
<ins>Inputs:</ins> 
Information for each step in the run sheet, user credentials and user roles/responsibilities
<br>
<ins>Outputs:</ins> 
Filtered run sheets with each step, including performance title, action, role and notes
<br>
<ins>User Interface:</ins>
Users must be able to interact with the software on a desktop or laptop, which would be placed in a highly visible area for crew members to view. The user interface should be minimal and not cluttered.
<br>
<ins>Types of data required:</ins>
String, boolean, integer
<br>
<ins>Technical requirements:</ins>
App must be able to cache run sheets to enable offline functionality, app must be compatible with desktops and laptops, with optional support for mobile devices if time allows.
