# Error Handling & Logging – Can it recover from failures?
## Application handles errors gracefully (instead of crashing).
**What does this mean for my project? (If not relevant, say why.)** <br>
If any errors are to occur, users should be alerted in a way that does not expose internal security measures, and the error should be logged for future use. The app should fail in a controlled manner. For instance, if the run sheet cannot be obtained from the database, the application should not crash, but continue to display the current instruction. If applicable, API requests should be retried if it is out of the user's control (i.e. there is no input that triggers it).

**How and when will I check this?** <br>
Some errors can be hard to force, requiring specific conditions. This criteria will be checked through manual inspection of the code. It will also be uncovered while running unit and integration tests.

## Try-catch blocks (or equivalent) are used for handling errors.
**What does this mean for my project? (If not relevant, say why.)** <br>
In the back-end, which uses Python, try-except blocks should be used to gracefully handle errors. The front-end, which will use JavaScript should have try-catch blocks to handle errors. While developing code, errors should be anticipated and built into the code rather than added later. 

**How and when will I check this?** <br>
This will be checked throughout the Producing and Implementing phase by manually reviewing code and performing automated tests, which will highlight unhandled errors.

## Error messages help the user understand what went wrong.
**What does this mean for my project? (If not relevant, say why.)** <br>
Users should be able to view easy to understand error messages which briefly describe the issue in a way that does not expose the internal logic. If retrieving run sheets from the database failed because of a misconfigured URL, users might recieve a pop up that says "Connection to server failed".

**How and when will I check this?** <br>
This will be checked throughout the development process by testing the web application manually. It may also be assessed by obtaining client feedback on the user experience.

## Errors and warnings are logged (for debugging).
**What does this mean for my project? (If not relevant, say why.)** <br>
Any errors on the front-end should be sent to the back-end server and saved in a file. The back-end Flask server should save any errors in a file, using a Python library, for debugging purposes. Flask provides a debug mode that logs errors, and JavaScript often logs simple errors, but logging specific errors will make it quicker and easier to debug.

**How and when will I check this?** <br>
This will be manually checked throughout the Producing and Implementing stage.
