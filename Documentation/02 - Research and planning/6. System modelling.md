# Storyboard
A storyboard was chosen to represent my software system. It is a visual representation of the software's user interface and user experience, conveying how users will navigate through and interact with the software.

Using a storyboard as a modelling tool enhances communication with stakeholders. For clients to understand and holistically grasp the essence of the project, it greatly benefits if they have prior knowledge of backstage operations and live productions. Storyboards visualise the user interface and interactions which allows the project concept to be tangible and easily understandable. Since it is so easily understandble, stakeholders can provide better feedback, and rapid prototypes of storyboard designs can be created. In turn, this improves the UI/UX of the software. It will specifically benefit the user interface used to edit and create run sheets. Rapid prototypes allow this user interface to be improved and streamlined, aligning with the [desired outcomes](../01%20-%20Identifying%20and%20defining/2.%20Scenario%20Details.md#desired-outcome) (to reduce the effort involved in making and reading run sheets).

The storyboard also shows the flow of the software and how users will navigate between different screens. This provides a detailed outline of what UI components need to made in the Producing and Implementing stage, acting as a framework to guide development. This ultimately reduces production time and saves time, which is critical for the given time constraints.
