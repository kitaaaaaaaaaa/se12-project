# Deployment & Version Control – Is it properly managed?
## The project is stored in GitLab
**What does this mean for my project? (If not relevant, say why.)** <br>
The project files - journal, report, presentation and software is stored and pushed to Gitlab.

**How and when will I check this?** <br>
This does not need to be checked. It is the basis of the project, where all worked is continually saved.

## Uses a proper branching strategy (main, dev, feature-branch).
**What does this mean for my project? (If not relevant, say why.)** <br>
The project on Gitlab should have separate branches to keep the main branch clean and organised. The project will have the following branches:
- main: the main copy of the project
- docs: where documentation can be written and hastily drafted
- dev: a development branch to store all of the code
- feat/feature-branch: a new branch for each feature

**How and when will I check this?** <br>
This will be checked in the Gitlab repository graph before a new sprint in the Producing and Implementing phase. A new branch will be created before each sprint, with additional branches being created if neccessary.

## Deployment process is documented and repeatable.
**What does this mean for my project? (If not relevant, say why.)** <br>
The code will not be deployed on a web server, but the project will be made ready for deployment. When a new version of the code is pushed to the dev branch, unit tests, integration tests and SAST tests will be ran. This ensures that there are no errors and that it is ready for deployment in the future.

**How and when will I check this?** <br>
This will be checked at the start of the Producing and Implementing phase when I am setting up the code structures. It will also be reviewed throughout the producing and implementing phase, as I will have a checklist next to me while working on the project.

## The latest stable version is tested before deployment.
**What does this mean for my project? (If not relevant, say why.)** <br>
Before merging the dev branch to the main branch, the code should be fully tested in order to ascertain if the code works.

**How and when will I check this?** <br>
The latest version will undergo automated unit and integration testing. After which, functional testing will be employed, ensuring the app fulfills the functional requirements.
