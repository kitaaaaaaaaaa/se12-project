# Performance – Is it fast and efficient?
## Page load times are optimized (e.g., lazy loading, minified assets).
**What does this mean for my project? (If not relevant, say why.)** <br>
Every page - from homepage to live run sheet should load in a timely manner. Images and videos, if used should utilise lazy loading so that they are loaded only when they are needed. The loading of scripts should also be deferred. The app must also use efficient caching strategies, enabled by a service worker.

**How and when will I check this?** <br>
This will be thouroughly checked during the Testing and Evaluating page to assess the load times of the application in its entirety. Assessing it prior to the software's completion could lead to inaccurate load times. This will be checked using browser developer tools using the 'Performance' tab. The browser tools also allows for easy, quick assessments of webpage load times during production and implementation, reducing the need for comprehensive performance improvements later.


## Database queries are optimised (e.g., indexed where needed).
**What does this mean for my project? (If not relevant, say why.)** <br>
The project will store event, run sheet and user data in a SQLite database. The back-end server should use asynchronous processes[^1] - this means that the server will continue to write to the database without waiting for the data to be physically written.

**How and when will I check this?** <br>
The code will be peer reviewed and evaluated before the production of the event admin dashboard. Peers will be specifically looking for code that alters SQLite database settings in order to support asynchronous processes.

## Unnecessary code or API calls have been removed.
**What does this mean for my project? (If not relevant, say why.)** <br>
During the Producing and Implementing stage, unnecessary and redundant code may be kept for development reasons. Code and API calls may be added for debugging, which becomes unnecessary when deploying the software, and should be removed.

**How and when will I check this?** <br>
This will be checked after each sprint, before commencing work on the next feature. It will be checked through code review.

## Caching is used where applicable (e.g., images, API responses).
**What does this mean for my project? (If not relevant, say why.)** <br>
The software should cache run sheets and instructions recieved by the API, saving it to local storage. The app should also cache the HTML/CSS/JS files required to display the user interface.

**How and when will I check this?** <br>
Caching will be checked and incrementally implemented towards the end of each sprint. This involves the inspection of the service worker file, as well as the use of browser developer tools to view if the data is actually cached.

[^1]: *SQLite Optimizations For Ultra High-Performance 2023*, Powersync.com, viewed 28 April 2026, \<https://www.powersync.com/blog/sqlite-optimizations-for-ultra-high-performance>.
