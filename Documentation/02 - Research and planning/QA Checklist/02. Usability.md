# Usability – Is it user-friendly?

## The UI/UX (user interface/user experience) is clear, intuitive and easy to navigate
**What does this mean for my project? (If not relevant, say why.)** <br>
The homepage makes it easy to manage different run sheets, and should adopt a similar look to existing solutions (Google Drive). Editing run sheets and adding instructions should be intuitive and require similar, or less effort when compared to the existing solution of a spreadsheet. The user interface should also be clear, making it easy for users to find information.

**How and when will I check this?** <br>
The clarity of the user interface will be checked during the Research and Planning phase. Interface designs will be created and shared with clients to obtain feedback from multiple age ranges. The user experience will be checked during the Testing and Evaluating phase. The completed software solution will be given to clients and possibly new users with little to no explanation. If they can use the software successfully, the criteria is fulfilled.

## Forms provide useful validation messages (e.g., "Password too short").
**What does this mean for my project? (If not relevant, say why.)** <br>
When users create/enter login details or make run sheets, users should be alerted if their inputs are invalid. This might come in the form of a pop up, or red text next to the input field to make it obvious.

**How and when will I check this?** <br>
This will be checked throughout production and implementation, since features are tested at the end of each sprint. It will also be re-checked during the Testing and Evaluating phase while obtaining feedback from users and clients.

## Accessibility considerations (e.g., readable fonts, color contrast).
**What does this mean for my project? (If not relevant, say why.)** <br>
The web application should respond to users zooming in or out - font sizes must change accordingly and the UI must adjust itself so that the website is still readable. Colours should not be too similar to each other. As a optional feature, the software should also have an ability to toggle between light and dark modes for those with visual impairments.

**How and when will I check this?** <br>
Changes in font sizes and toggles between light and dark mode will be tested during its development. Colour palettes will be checked in the Research and Planning phase to ensure that they have a certain contrast ratio that aligns with WCAG guidelines. In the Testing and Evaluating phase, a browser extension will be used to test accessibility features on the website.

## Buttons, menus, and inputs are clearly labeled and responsive.
**What does this mean for my project? (If not relevant, say why.)** <br>
Any buttons, menus and inputs in the event administrator home page, authentication pages or live run sheet pages should be clearly labelled with its function. If not, there should be a recognizable icon that also has alt text to support screen readers.

**How and when will I check this?** <br>
This will be checked in the Testing and Evaluating phase - after I have separated myself from the development and inner workings of the project so that I can bring an unbiased perspective. I will manually look at every page and assess this criteria.
