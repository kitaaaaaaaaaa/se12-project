# Testing – Has it been properly tested?
## Unit tests check individual functions/components.
**What does this mean for my project? (If not relevant, say why.)** <br>
As a priority, the project will have unit tests for back-end functions using the Pytest library. Unit tests have to be written during development. It should check that back-end functions produce the expected result. The results of all unit tests should be easily viewable in one place. The front-end may have unit tests, using a custom built testing script in this [article](https://alexwlchan.net/2023/testing-javascript-without-a-framework/).

**How and when will I check this?** <br>
This will be checked after each sprint in the Producing and Implementing phase. If unit tests have not been written for a specific function, it will be added to the next sprint as the first course of action. Unit tests will be ran periodically throughout the development process.

## Integration tests ensure different parts of the system work together.
**What does this mean for my project? (If not relevant, say why.)** <br>
Test will be written which involves making requests to the back-end. The project will use Pytest to simulate interactions between the front-end and the back-end, checking if the returned response is correct. This will check if the back-end server is correctly returning run sheet instructions, user data etc.

**How and when will I check this?** <br>
Integration tests will be written during the Producing and Implementing phase in a hybrid approach[^1] (if dependencies are missing, temporary stubs will be placed). They will be ran after each sprint.

## User testing was conducted for feedback.
**What does this mean for my project? (If not relevant, say why.)** <br>
Users should be consulted throughout the project regarding UI/UX decisions. UI designs and drafts will be sent to users for feedback. The completed web app must be shared with the user to make sure that it is intuitive, and the functionality should be changed according to the feedback.

**How and when will I check this?** <br>
This will be checked when UI designs are finished in the Research and Planning stage. I will also check this during the Testing and Evaluating phase to see if the summary of feedback has been filled out.

## Bugs and issues were documented and resolved.
**What does this mean for my project? (If not relevant, say why.)** <br>
Gitlab will be used to document and keep track of bugs and issues in order to document the process. Issues will generally be tracked in my own choice of task management app (Todoist). The issues on Gitlab/Todoist will be transferred to the project documentation if needed.

**How and when will I check this?** <br>
This will be checked throughout the Producing and Implementing process when writing journal entries and documenting project challenges. This will be done while reflecting on the week and reviewing task history in Todoist.
